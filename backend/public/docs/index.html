Authentication

All authenticated endpoints require an API key passed via the X-API-Key header:

curl -H "X-API-Key: dsk_your_key_here" \
  https://api.tapprove.io/api/v1/stats

Alternatively, use Authorization: Bearer dsk_... — the key must start with dsk_.

Keys are scoped. Each endpoint lists its required scope. Your key must include that scope or you'll get a 403 insufficient_scope error.

Base URL

https://api.tapprove.io/api/v1

POST /offers/:id/share

No auth required. Called when a user taps Share in the app. Increments share_count and dispatches offer.shared webhook.

GET /offers/:id/preview.png

No auth required. Returns a branded 1200×630 PNG for Open Graph / social sharing.

POST /webhooks

Scope: webhooks:write — Register a new webhook endpoint.

The URL is tested with a POST before saving. If it doesn't return 2xx, registration is rejected.

{
  "url": "https://example.com/hooks/dander",
  "events": ["offer.created", "coupon.redeemed"],
  "secret": "your-shared-secret-min-16-chars"
}

GET /webhooks

Scope: webhooks:write — List all registered webhooks. Secret is never returned.

DELETE /webhooks/:id

Scope: webhooks:write — Soft-delete (deactivates the webhook).

GET /webhooks/:id/deliveries

Scope: webhooks:write — Last 50 delivery attempts. Useful for debugging failed integrations.

Kilo IoT Integration

TapProve supports IoT sensor integration for automatic footfall tracking and offer triggering. All Kilo endpoints require business session auth (/api/kilo/*).

Device Management

POST /api/kilo/devices

Register a new sensor device. Initial status: assigned.

{
  "device_id": "kilo_bel_0042",
  "label": "Front door counter",
  "lat": 54.5973, "lng": -5.9301
}

GET /api/kilo/devices

List all non-decommissioned devices for this business.

PUT /api/kilo/devices/:id

Update device label, location, or meta.

DELETE /api/kilo/devices/:id

Decommission device (soft delete).

Device lifecycle: assigned → active (on first reading) → offline / decommissioned

Sensor Readings

POST /api/kilo/devices/:deviceId/reading

Record a sensor reading. Stored in sensor_readings table. On the first reading, the device transitions from assigned to active and dispatches a device.first_reading webhook.

{
  "reading_value": 12,
  "device_type": "people_counter",
  "unit": "count",
  "meta": { "battery": "94%" }
}

Footfall Baselines

Baselines represent the average footfall per day-of-week + hour slot, calculated from the last 56 days of people_counter readings.

GET /api/kilo/baselines

Get all baselines for this business. Returns array of { day_of_week, hour_slot, avg_footfall, sample_count }.

POST /api/kilo/baselines/recalculate

Recalculate baselines from the last 56 days of sensor data. Upserts into footfall_baselines table.

// Response
{ "recalculated": true, "slots_updated": 84 }

Offer Trigger Fields

FieldTypeDescription
trigger_sourcestringOrigin of the offer: kilo_iot, stamplify, or manual (default)
trigger_device_idstringHardware ID of the triggering sensor
auto_expire_on_recoverybooleanIf true, the offer auto-expires when footfall returns to normal

Example flow: A Kilo sensor detects a quiet period (footfall drops below the baseline threshold). It creates an offer with trigger_source: "kilo_iot". When footfall recovers, it deactivates the offer. The footfall.alert webhook notifies subscribed systems.

Smart Specials

Upload a photo of your stock or display. The system matches visible items against your inventory, flags perishables with urgency levels, and suggests discount offers automatically.

POST /smart-specials/assess

Scope: smart_specials:read — Upload a photo for assessment. Send as multipart/form-data with a photo field. Optionally pass labels (JSON array of detected item names).

// Response 201
{

    "assessment_id": 7,
    "photo_url": "https://res.cloudinary.com/...",
    "items": [
      { "inventory_id": 3, "name": "Sourdough loaf", "is_perishable": true, "confidence": 0.85 }
    ],
    "freshness_flags": [
      { "item_name": "Sourdough loaf", "urgency": "high", "label": "Use today", "discount": 40 }
    ],
    "suggested_offers": [
      { "title": "40% off Sourdough loaf — use today", "offer_type": "percentage", "discount_percent": 40 }
    ]
  }
}

GET /smart-specials/history

Scope: smart_specials:read — Returns the last 30 photo assessments for this business, ordered by most recent first.

Webhook Events

TapProve sends a POST to each registered webhook URL when events occur. The payload is signed with HMAC-SHA256 using your shared secret, sent in the X-Dander-Signature header.

EventTriggered when
offer.createdA new offer is published
offer.updatedAn offer is edited
offer.deactivatedAn offer is deactivated
offer.sharedA shopper shares an offer
coupon.redeemedA coupon is redeemed at the counter
story.postedA business posts a daily story
device.first_readingIoT device sends its first sensor reading
footfall.alertFootfall drops below threshold — quiet period detected
footfall.recoveryFootfall returns above threshold — quiet period ended

{

    "discount_percent": 20,

}

Verifying signatures

// Node.js example
const crypto = require('crypto');

const expected = crypto
  .createHmac('sha256', YOUR_SHARED_SECRET)
  .update(rawRequestBody)
  .digest('hex');

if (signature !== expected) {
  return res.status(401).json({ error: 'invalid_signature' });
}

API Scopes

Each API key is assigned one or more scopes that control which endpoints it can access. Request the scopes you need when creating a key.

ScopeGrants access to
stats:readGET /stats, GET /weather/correlation
sensors:readGET /kilo/devices, GET /kilo/baselines
sensors:writePOST /kilo/devices, PUT/DELETE devices, POST readings, POST recalculate
smart_specials:readPOST /smart-specials/assess, GET /smart-specials/history
smart_specials:writeReserved — approve/publish suggested offers (future)
webhooks:writePOST/GET/DELETE /webhooks, GET /webhooks/:id/deliveries
Tip: Use the minimum scopes needed. A key with stats:read cannot modify offers or register webhooks.

Rate Limits

100 requests per minute per API key. Every response includes these headers:

HeaderDescription
X-RateLimit-LimitMax requests per window (100)
X-RateLimit-RemainingRequests remaining in this window
X-RateLimit-ResetUnix timestamp when the window resets
Retry-AfterSeconds to wait (only on 429 responses)

Getting Your API Key

  1. Sign in to the TapProve Business Dashboard
  2. Navigate to Settings → API Keys
  3. Click Create API Key
  4. Choose a label and select the scopes you need
  5. Copy the key immediately — it won't be shown again
Security: Keys are stored as SHA-256 hashes. If you lose your key, revoke it and create a new one.
